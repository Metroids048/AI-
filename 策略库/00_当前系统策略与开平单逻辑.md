# 当前系统策略与开平单逻辑

## 当前可用通道

### 1. Funding carry 通道

定位：资金费率/基差套利优先通道，用来跑稳 Data -> Validation -> Execution -> Review 闭环。

开单条件：

- `entry_rules.funding_threshold_bps`：资金费率阈值。
- `entry_rules.min_estimated_net_edge_bps`：扣除 fee/slippage 后的最小净边际。
- `entry_rules.requires_positive_funding`：默认只做正资金费率场景。
- `MarketQueryService.get_funding_arbitrage_signal` 必须给出 `should_enter_paper=true`。

方向：

- 正 funding 且策略要求正 funding：偏向 short perp 收取 funding。
- 负 funding 只有在策略显式允许时才考虑 long perp。

拒绝原因：

- `negative_net_edge`
- `below_funding_threshold`
- `below_min_estimated_net_edge`
- `requires_positive_funding`

### 2. Technical directional 通道

定位：方向性策略通道，先用于 Binance Testnet/Paper，不直接承诺 live。

当前默认规则：

- `timeframe_model = 4h_direction_15m_entry`
- `direction_timeframe = 4h`
- `entry_timeframe = 15m`
- `enabled_signals = macd, dow_trend, price_action, rsi, ema_trend, adx, vwap, bollinger`
- `meta_label_min_win_rate = 0.48`

信号来源：

- MACD：交叉与 histogram 动量。
- Dow trend：高低点结构与连续趋势强度。
- Price action：吞没、pin bar、Donchian 突破、假突破/假跌破。
- RSI：超卖恢复、超买回落。
- EMA trend：快慢 EMA 顺势与斜率。
- ADX：方向性运动强度过滤。
- VWAP：重返/跌破 VWAP。
- Bollinger：布林带极端后回归。

系统变化：没有技术信号时，不再使用最后两根 K 线 fallback 开单，直接 `technical_signals_insufficient` 跳过。

## 开单链路

1. PaperRuntime 选择候选 symbol。
2. 对策略读取 `entry_timeframe`；若存在则以策略入场周期扫描，否则使用请求周期。
3. PaperSignalGenerator 判断 carry 或 directional。
4. Directional 进入 DecisionPipeline：技术信号 -> 多周期确认 -> SignalEnsemble -> MetaLabel -> LLM veto。
5. PaperSignalGenerator 生成 ExecutionOrderRequest，附 stoploss/takeprofit/position/risk_state。
6. Gatekeeper 检查止损、验证证据、数据新鲜度、风险事件、数值风控。
7. 如果 PaperRun 开启 Testnet mirror 且 `binance_auto_execute=true`，必须先提交 Binance gateway。
8. Binance 成功后，本地 Paper 才 fill 并写 PositionSnapshot。

## 平单逻辑

优先级：

1. 保护性止损/止盈：使用最新已成交入场单的 stoploss/takeprofit 计划，按 K 线 high/low 是否触发判断。
2. 同一根 K 线同时触发止损和止盈时，优先止损。
3. `trail_after_r` 达到配置 R 倍后，把止损收紧到入场价，且只收紧不放松。
4. 反向信号：`close_on_opposite_signal=true` 时先 close-only 平旧仓，不同一轮直接反手。
5. 无新信号：已有仓位继续由保护性退出管理。

Binance-first 语义：

- 如果启用 Testnet mirror，开仓和平仓都必须先提交 Binance gateway。
- gateway 成功后才本地 fill/open/close。
- gateway 失败时订单写为 `execution_status=rejected`、`gateway_status=gateway_failed`、`rejection_codes` 包含 `binance_auto_execute_failed`。
- gateway 失败不会本地开仓或本地平仓，避免 Testnet 和本地状态分叉。

## 仓位管理

当前规则：

- 固定 notional 优先级低于风险预算。
- 根据 stop distance 计算风险预算 notional。
- 受 `risk_per_trade`、`max_position_fraction`、`max_leverage`、`min_notional_usdt` 约束。
- 默认 directional 通道收紧到 `risk_per_trade=0.01`、`max_leverage=5`、`max_position_fraction=0.05`。

尚需加强：

- 实时账户权益与 Binance Testnet 仓位同步。
- 单 symbol 总风险、相关性风险、组合净敞口。
- OI/订单簿深度驱动的动态滑点与最大下单量。

## LLM + RAG 作用边界

允许：

- 对新闻、宏观、风险事件做分类。
- 对 signal ensemble 做 pre-execution veto。
- 对 Review 失败原因做总结。
- 从 `策略库/*.md` 和开源研究资产中检索上下文。

禁止：

- 直接输出买入/卖出方向。
- 直接决定价格、仓位、杠杆。
- 绕过 Gatekeeper、Validation 或 Review。
- 因 LLM 不可用而放宽风控。
