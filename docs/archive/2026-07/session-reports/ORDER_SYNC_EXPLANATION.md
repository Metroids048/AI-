# 订单同步说明 - 为什么本地订单数 ≠ 币安订单数

## 问题现象

- **本地系统**：显示 20 个订单
- **币安交易所**：只有 11 个订单

这是**正常的设计行为**，不是bug！

---

## 订单分类与同步规则

### ✅ **会同步到币安的订单**

| 订单来源 | 说明 | 是否同步 |
|---------|------|---------|
| **交易所保护止损（市价）** | `kind: binance_open_order` + `reduce_only: true` + `STOP_MARKET` | ✅ 是 |
| **交易所保护止盈（限价）** | `kind: binance_open_order` + `reduce_only: true` + `LIMIT` | ✅ 是 |
| **Binance 真实信号采样** | `kind: strategy_trade` + `lane: signal_observation` + 有 `gateway_order_id` | ✅ 是 |
| **主方向策略（开启镜像时）** | `kind: strategy_trade` + `lane: directional` + 镜像开关开启 | ✅ 是 |

### ❌ **不会同步到币安的订单（仅本地记录）**

| 订单来源 | 说明 | 是否同步 |
|---------|------|---------|
| **本地信号采样（不计策略收益）** | `kind: strategy_trade` + `lane: signal_observation` + 无 `gateway_order_id` | ❌ 否 |
| **手动模拟单** | 手动下单，无 `paper_run_id` | ❌ 否 |
| **自动策略（镜像关闭时）** | 有 `paper_run_id` 但镜像开关关闭 | ❌ 否 |
| **连通性验收（不计策略收益）** | `kind: testnet_acceptance` | ❌ 否 |
| **币安模拟盘补录（不计策略收益）** | `kind: binance_demo_reconciliation` | ❌ 否 |

---

## 为什么要这样设计？

### 1. **本地模拟盘 vs 币安模拟盘**

系统支持**双重模拟环境**：

```
┌─────────────────────┐
│   本地模拟盘        │  ← 所有订单都记录在这里（20个）
│  (Paper Trading)    │
└──────────┬──────────┘
           │
           │ 镜像开关 ON/OFF
           ↓
┌─────────────────────┐
│  币安模拟盘         │  ← 只有开启镜像的订单才会同步（11个）
│ (Binance Testnet)   │
└─────────────────────┘
```

### 2. **订单来源代码逻辑**

查看 `frontend/admin/src/components/TradingConsolePanels.jsx` 第 725-743 行：

```javascript
function orderSourceLabel(order) {
  const kind = order?.entry_context?.execution_kind;
  const lane = order?.entry_context?.strategy_lane;

  // ✅ 这些会同步到币安
  if (kind === "binance_open_order" && order?.entry_context?.reduce_only) {
    if (orderType === "STOP_MARKET") return "交易所保护止损（市价）";
    if (orderType === "LIMIT") return "交易所保护止盈（限价）";
    return "交易所保护单";
  }

  // ✅ 有gateway_order_id说明已经同步到币安
  if (kind === "strategy_trade" && lane === "signal_observation" && order?.gateway_order_id) {
    return "Binance 真实信号采样（不计策略收益）";
  }

  // ❌ 这些不会同步到币安（仅本地记录）
  if (kind === "strategy_trade" && lane === "signal_observation")
    return "本地信号采样（不计策略收益）";

  if (kind === "testnet_acceptance")
    return "连通性验收（不计策略收益）";

  // ❌ 手动模拟单不会自动同步
  return "手动模拟单";
}
```

### 3. **"不计策略收益"的含义**

订单标签中的**"不计策略收益"**表示：
- 这是**测试订单**或**观察订单**
- 用于验证系统连通性、采集市场数据
- **不会影响策略的真实收益计算**
- **不一定会同步到币安**

## 如何查看订单是否已同步到币安？

### 方法1：查看"网关"列

在本地系统的订单列表中，查看**"网关"列**：

- **有值**（如 `binance_usdt_perpetual`）→ ✅ 已同步到币安
- **`-`** 或空 → ❌ 仅本地记录

### 方法2：查看"币安 ID"列

- **有数字ID**（如 `33961591882`）→ ✅ 已同步到币安
- **`--`** → ❌ 仅本地记录

### 方法3：查看订单来源

- 包含**"交易所"**字样 → ✅ 已同步
- 包含**"本地"**字样 → ❌ 仅本地
- 包含**"不计策略收益"** → 可能是测试订单，不一定同步

---

## 如何让更多订单同步到币安？

### 开启 Testnet 镜像

在本地系统的**"自动交易"面板**中：

1. 找到"开启 Testnet 镜像"按钮
2. 点击开启
3. 开启后，**策略信号会先提交币安**（`BINANCE_AUTO_EXECUTE`）
4. 成功后才本地成交

开启镜像后的行为：
```
用户下单
  ↓
本地生成订单记录
  ↓
立即发送到币安 API  ✅
  ↓
币安返回 order_id
  ↓
更新本地订单的 gateway_order_id
```

不开启镜像时：
```
用户下单
  ↓
仅在本地数据库记录  ❌
  ↓
不发送到币安
```

## 常见问题

### Q1: 为什么要保留仅本地的订单？

**A:**
1. **快速回测验证**：不需要真实网络请求，速度更快
2. **避免交易所限流**：高频测试不会被币安API限流
3. **成本控制**：即使是模拟盘，频繁API调用也可能触发限流
4. **分离测试和生产**：测试订单不应该污染真实的模拟盘账户

### Q2: 我想让所有订单都同步到币安，怎么办？

**A:**
1. 开启"Testnet 镜像"开关
2. 确认代理 `127.0.0.1:7890` 正在运行
3. 确认币安 API 凭证已配置（`.env` 文件）

### Q3: 币安的订单比本地少，会影响策略收益计算吗？

**A:** 不会！
- **策略收益以本地记录为准**
- 币安的订单只是"镜像"，用于验证真实市场执行效果
- 所有标记为"不计策略收益"的订单，无论是否同步，都不会影响最终收益

### Q4: 如何确认某个订单确实在币安执行了？

**A:** 三个验证方法：
1. 本地订单列表中，该订单的"币安 ID"列有数字
2. 本地订单列表中，该订单的"网关"列有值
3. 登录币安模拟盘网页，在"Order History"中能找到对应的订单

## 总结

**本地20个订单，币安11个订单** = ✅ **正常行为**

- 本地系统是"订单记录中心"，记录所有订单（包括测试、模拟、真实）
- 币安是"执行中心"，只记录真正需要在交易所执行的订单
- 标记为"不计策略收益"的订单，通常是测试或观察用途，不会同步到币安
- 要增加同步到币安的订单数，需要开启"Testnet 镜像"开关

这种设计让系统既能快速测试，又能在需要时与真实交易所同步！
