# 配置变更交付检查清单

## 问题背景

2026-07-16发现严重问题：昨天修改了代码配置（bootstrap.py、risk.py、universe.py），创建了文档，但**没有重启系统**，导致配置完全没有生效，跑了一整晚仍是旧配置。

## 根本原因

**错误理解了"任务完成"的定义**：
- ❌ 错误理解：修改代码 = 任务完成
- ✅ 正确理解：修改代码 + 重启系统 + 验证生效 = 任务完成

## 强制执行规则

### 对于任何涉及配置变更的任务，必须执行以下步骤：

#### 1. 修改代码文件
- 修改配置相关的代码文件
- 使用Read工具验证代码修改已落地

#### 2. 明确告知用户需要重启 ⚠️
**这是最容易遗漏的步骤！**

必须明确告诉用户：
```
⚠️ 配置修改完成，但需要重启系统才能生效！

请执行以下步骤：
1. 停止所有进程：完全重启系统.cmd
2. 重新启动：一键启动.cmd
3. 运行验证：python scripts/verify_config.py
```

**禁止**只说"配置已完成"而不提重启！

#### 3. 等待用户确认重启
- 不要假设用户会自己重启
- 明确等待用户确认"已重启"
- 如果用户没有确认，不得进行下一步

#### 4. 验证数据库配置
重启后，必须验证数据库中的配置已更新：
```python
import sqlite3
conn = sqlite3.connect('.local_paper_console.db')
cursor = conn.cursor()

# 检查配置是否写入数据库
cursor.execute('SELECT auto_trading_settings FROM paper_runs WHERE paper_status = "running"')
# 验证配置值
```

#### 5. 验证运行时行为
检查实际运行情况：
- 扫描的币种是否符合预期
- 拒单原因是否改变
- 订单的entry_context中的参数是否正确

#### 6. 所有验证通过后才能声明完成
只有当以上所有步骤都通过，才能说"任务完成"。

## 配置变更类型识别

以下类型的变更属于"配置变更"，必须执行本检查清单：

### 明确的配置变更
- ✅ 修改`bootstrap.py`中的策略配置
- ✅ 修改`risk.py`中的风险参数
- ✅ 修改`universe.py`中的币种列表
- ✅ 修改`.env`环境变量
- ✅ 修改数据库schema（Alembic迁移）

### 隐含的配置变更
- ✅ 修改策略规则（entry_rules、exit_rules、position_rules）
- ✅ 修改费率/滑点假设
- ✅ 修改风控阈值
- ✅ 修改信号生成逻辑的参数

### 不需要重启的变更
- ❌ 纯新增API接口（不改现有逻辑）
- ❌ 新增文档
- ❌ 修复不影响运行时配置的bug
- ❌ 前端样式调整

## 本次失误的具体案例

### 应该做但没做的：

1. ❌ **没有告诉用户必须重启系统**
   - 只说了"配置完成"
   - 没有提供重启命令
   - 没有解释为什么需要重启

2. ❌ **没有验证配置是否生效**
   - 没有检查数据库
   - 没有检查运行时行为
   - 假设"修改代码=配置生效"

3. ❌ **没有等待用户确认**
   - 直接声称"完成"
   - 没有建立验证反馈循环

### 正确的做法应该是：

1. ✅ 修改代码文件
2. ✅ Read验证代码修改
3. ✅ **明确告诉用户**：
   ```
   配置修改完成！但必须重启才能生效。

   请立即执行：
   1. 运行 完全重启系统.cmd
   2. 等待系统启动完成
   3. 运行 python scripts/verify_config.py
   4. 将验证结果告诉我

   在你确认重启前，我不能声明任务完成。
   ```
4. ✅ 等待用户回复验证结果
5. ✅ 根据验证结果判断是否真正完成
